# OfficeFlow AI — AI 업무비서 2.0

**원래의 AI 업무비서 업무 흐름을 유지하면서 운영 안정성을 추가한 로컬 실행형 고도화 프로젝트**입니다.

기존 저장소: [ai-office-assistant](https://github.com/rlaqhfla0917-bit/ai-office-assistant)  
이 프로젝트는 기존 저장소를 덮어쓰지 않고 별도로 구현한 **2.0 버전**입니다. 기존 코드를 그대로 복제하거나 동일한 LangGraph 파일을 재사용한 것은 아닙니다. 필요하다면 아래 원본 SQLite 데이터 가져오기 기능으로 업무 기록을 이전할 수 있습니다.

## 1. 무엇이 달라졌나요?

| 기존 AI 업무비서 | 2.0 고도화 |
| --- | --- |
| 연차·업무 DB 조회 | 직원별 접근 범위 확인, 같은 대화의 후속 업무 질의 |
| 사내 규정·회의록 검색 | 문서 근거 반환; 실제 AI 모드에서 검색 문서를 모델 입력으로 사용 |
| 회의 음성 STT·업무 추출 | 회의 텍스트 추출 결과를 미리보기 후 **사용자 승인** 시 저장 (음성 STT는 현재 미포함) |
| 이메일 발송/업무 변경 데모 | **승인 필수** 작업 큐 + 영구 상태 저장 + 재시도 + 실패함(DLQ) |
| 실행 상태 확인 제한 | 운영 대시보드에서 승인·진행·성공·실패·감사 로그 조회 |
| 단일 Python CLI | FastAPI 웹 화면 + 독립 Worker + Docker Compose + Redis 신호 |

### 핵심 흐름

```text
직원 질문 → SQL 업무 조회 / 사내 규정 검색 → 근거가 있는 답변
회의록 텍스트 → 업무 추출 미리보기 → 직원 검증 → 업무 DB 저장
메일·상태 변경 요청 → 승인 대기 → 승인 → 작업 큐
    ├── 성공: DB 변경 또는 모의 발송함 기록
    └── 실패: 지수형 재시도(최대 3회) → 실패함(DLQ) → 수동 재처리
                                          ↳ 운영 화면·감사 로그
```

## 2. 비용 — 중요

- **기본 실행: 무료.** 기본값 `AI_MODE=offline`. 이 모드에서는 **진짜 LLM이 호출되지 않습니다.** 문서 검색은 키워드 매칭, 회의록 추출은 안내된 형식 파서입니다.
- **실제 AI 연결: 유료 가능성 있음.** `AI_MODE=openai` 와 `OPENAI_API_KEY`를 본인이 명시적으로 설정한 경우에만 API를 호출합니다. 사용량에 따라 OpenAI API 요금이 발생할 수 있습니다. *ChatGPT 구독과 API 요금은 별개*입니다.
- **Docker + 로컬 Redis: 프로그램 자체 무료.** PC의 설치·전력·네트워크 환경 비용은 별도입니다. AWS 리소스를 생성하거나 배포하는 코드는 실행하지 않습니다.
- `.env` 및 API 키는 GitHub에 올리지 마세요.

## 3. Windows PowerShell에서 바로 실행

**Python 3.10 이상**이 필요합니다. 압축을 풀고 해당 폴더에서 다음을 실행하세요.

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m uvicorn officeops.web:app --host 127.0.0.1 --port 8501
```

브라우저에서 **http://127.0.0.1:8501**을 엽니다.

`작업 승인·처리` 화면에서 작업을 승인한 뒤, `운영 대시보드`의 **작업 1건 실행 (로컬 데모)** 버튼을 누르면 워커 처리를 시연할 수 있습니다.

### 별도 워커를 실행하고 싶다면

다른 터미널에서:

```powershell
.venv\Scripts\python.exe -m officeops.worker
```

## 4. Docker Compose — 무료 로컬 운영

Docker Desktop을 설치한 경우:

```bash
docker compose up --build
```

- Web: localhost:8501
- Worker: 별도 Python 프로세스
- Redis: 작업 대기 시 깨우는 신호만 담당. 작업 상태는 SQLite에 영구 저장합니다.

> Docker 버전에서는 수동 Worker 버튼을 비활성화합니다. Redis 신호가 실패해도 DB 폴링으로 대기 작업을 찾아 처리하도록 설계했습니다. **별도 인증이 없는 로컬 시연용**이며 외부 인터넷에 직접 노출하면 안 됩니다.

## 5. 사용 예시

1. **AI 업무비서**: `내 업무 알려줘`, `출장비 규정 알려줘`, `김대리 업무 알려줘`, 이후 `그중 아직 안 끝난 업무는?`
2. **회의록 처리**: 예시의 `담당: 김대리 | 할 일: ... | 마감: YYYY-MM-DD`를 미리보기 후 승인 등록
3. **작업 승인·처리**: 모의 메일 요청 → 승인 → Worker 1회 실행 → 완료 및 모의 발송함 저장
4. **장애 대응 테스트**: `일시적 오류 후 성공` 작업 승인 → 첫 처리 실패 → 재시도 대기 → 재시도 후 성공
5. **실패함 테스트**: `영구 오류 테스트` 승인 → 3차례 처리 실패 → `dead_letter` → 수동 재처리

## 6. 기존 프로젝트 데이터 가져오기

기존 `ai-office-assistant`의 **meeting_agent.db**가 있는 경우:

```bash
python scripts/migrate_original.py /path/to/meeting_agent.db
```

원본 DB를 읽기 전용으로 열고 새 DB로 직원·업무·회의·휴가를 복사합니다. 매핑되지 않은 담당자는 임의로 추정해 저장하지 않습니다. 재실행하면 중복 임포트하지 않습니다. **기존 Chroma Vector DB나 음성 파일은 가져오지 않습니다.**

## 7. 테스트

```bash
python -m pytest -q
```

자동화 테스트는 사용자 권한, 회의록 확인·저장, 작업 승인·거절, 중복 요청 방지, 모의 메일, 재시도, 실패함, 감사 로그, 후속 질의, 데이터 가져오기 등을 확인합니다.

### 입증한 것과 아직 하지 않은 것

**로컬에서 실제 검증:** 웹 API 동작, SQLite 기반 영구 작업 이력, 승인 및 권한 규칙, 모의 발송, 오류 재시도 및 실패함 전환, 오프라인 실행, Docker 설정 파일의 존재.

**아직 검증하지 않음:** 실제 OpenAI API 응답(키 미사용), AWS 배포·CloudWatch 운영, Docker Compose 실행(테스트 환경에 Docker 없음), 실제 SMTP 메일 발송, 동시 사용자 성능·운영 SLA, 실제 STT. Redis 신호 경로는 선택 기능이며 외부 Redis 통합 테스트는 수행하지 않았습니다.

현재의 일반 사용자·팀장 선택은 **데모 역할 시뮬레이션일 뿐 실제 로그인 인증이 아닙니다.** 프로덕션 도입 시 인증·권한 검증, 보안 로그, 비밀키 관리, 외부 DB, 워커 수평 확장, 개인정보 처리정책이 필요합니다.

## 8. 기술

`Python` · `FastAPI` · `SQLite` · `Redis (선택)` · `Docker Compose` · `OpenAI API (선택)` · `pytest`

기존 프로젝트의 LangGraph Agent를 직접 재사용한 것은 아닙니다. 2.0은 동작 검증이 가능한 워크플로 엔진을 별도로 구현한 개선 시제품입니다.
